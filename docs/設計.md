# 設計

各ソースの冒頭にも設計思想をコメントで書いてある。ここはその全体像。

---

## 1. このアプリが何をしないか

作るものを決めるより、作らないものを決めるほうが効いている。

| しないこと | 理由 |
|---|---|
| **OAuth トークンを自分でリフレッシュしない** | 失敗すると Claude Code 本体のセッションが壊れる。数字が出ないより遥かに困る |
| **`~/.claude` に書き込まない** | 本体のデータ。読むだけ |
| **未文書化のシェル API を使わない** | タスクバーへの埋め込みや Deskband は Windows Update で壊れる |
| **しきい値を自前で決めない** | サーバーの `severity` に従う。公式 UI と食い違わせない |
| **設定画面を作らない** | 個人用ツールに見合わない。よく使うものだけメニューに出す |
| **ログライブラリを入れない** | 70 行で足りる。常駐アプリの依存は少ないほどよい |

被害の非対称性がすべての判断の軸になっている。このツールが動かなくても
「使用量が分からない」だけだが、本体を壊すと仕事が止まる。迷ったら
本体に触らないほうを選ぶ。

## 2. なぜ「画面上のパネル」なのか

最初は macOS のメニューバーアプリの移植として、Windows の通知領域（トレイ）に
実装した。これは失敗だった。

| | macOS メニューバー | Windows 通知領域 |
|---|---|---|
| 置けるもの | **可変幅のテキスト** | **16×16 のアイコン 1 枚だけ** |
| 既定の可視性 | 常に見える | **Windows 11 は既定でオーバーフロー（∧）に隠す** |

つまり Windows のトレイでは、

1. 5 時間・週次・モデル別を **同時に見せられない**（2〜3 文字しか入らない）
2. 状態を見るのに **毎回クリックが要る**

という、元の要求（常に見えていてほしい）と正反対のものになる。

タスクバーに直接描く方法も検討したが全滅した。

| 方式 | 判定 |
|---|---|
| Deskband (`IDeskBand`) | Windows 11 の XAML タスクバーが非対応 |
| デスクトップツールバー | Windows 11 で機能ごと削除 |
| `SetParent` でタスクバーに埋め込む | 未文書化。24H2/25H2 で位置ずれの不具合が継続 |
| ウィジェットボード | 開いたときしか見えない |

残ったのが **最前面の小さなパネルをデスクトップに置く** 方式。使うのは
`Form` と拡張スタイルという枯れた公開 API だけで、文字数の制約も無い。

### 拡張スタイルの意味

| フラグ | 役割 |
|---|---|
| `WS_EX_LAYERED` | 半透明にする |
| `WS_EX_TRANSPARENT` | クリックを下へ素通りさせる（既定は付けない） |
| `WS_EX_TOOLWINDOW` | Alt+Tab とタスクバーに出さない |
| `WS_EX_NOACTIVATE` | クリックしてもフォーカスを奪わない |

> **落とし穴**: `WS_EX_TRANSPARENT` を `SetWindowLongPtr` で後付けするだけでは
> 足りない。`Opacity` を変えると WinForms が `CreateParams` から拡張スタイルを
> 作り直してフラグを消す。`CreateParams` 側に含めておくこと。

## 3. データの取り方

```
GET https://api.anthropic.com/api/oauth/usage
  Authorization: Bearer <accessToken>     ← ~/.claude/.credentials.json から
  anthropic-beta: oauth-2025-04-20
  User-Agent: claude-cli/<本体のバージョン> (external, cli)
```

公開ドキュメントに無い内部エンドポイント。Claude Code 本体のバイナリから
見つけた。非公開 API に依存するのは本来避けたいが、代替が無い。

### 代替案を落とした理由

| 方法 | なぜ駄目か |
|---|---|
| ローカルの JSONL を解析 | トークン数は出せるが、**リミットの分母が非公開**なので消費率 % を出せない。本アプリの主目的が % なので不可 |
| Admin API | 組織の API 従量課金の集計。サブスクのリミットとは無関係で、レスポンスにレート制限ウィンドウの概念すら無い |
| claude.ai の Web API | `sessionKey` Cookie が要り、Cloudflare に弾かれる報告が多い |
| statusLine フック | 同じ `rate_limits` が取れるが、**Claude Code が起動中しか動かない** |

### それでも壊れにくいと考える根拠

`/usage` スラッシュコマンド・VS Code の usage パネル・statusLine の
`rate_limits` が、すべてこのエンドポイントに依存している。Anthropic 側にも
壊しにくい動機がある。

### 壊れたときのための保険

- 未知フィールドは無視する（サーバー側スキーマは passthrough）
- 成功レスポンスの生 JSON を常に `cache\last-usage.json` に残す。
  スキーマが変わったとき diff を取れる唯一の手がかり
- パース失敗時は生ボディを `cache\last-error-body.txt` に残す
- 撤退先として statusLine 経由の取得がある（未実装）

## 4. `limits[]` だけで分類する

レスポンスには `five_hour` / `seven_day` のほか `nimbus_quill` /
`cinder_cove` / `tangelo` / `harbor_lantern` といったコードネームの窓が
20 個近く並んでおり、その大半は `null`。

サーバー側の内部スキーマにこう書かれている。

> Classify a row on this, never on a label.

だから **`limits[]` の `kind` だけ** を見る。

```json
{ "kind": "session",       "percent": 35, "severity": "normal",  "resets_at": "..." }
{ "kind": "weekly_all",    "percent": 89, "severity": "warning", "resets_at": "..." }
{ "kind": "weekly_scoped", "percent": 0,  "severity": "normal",
  "scope": { "model": { "display_name": "Fable" } } }
```

この方針から自動的に決まること。

- **`kind` と `severity` を enum にしない。** 未知の値が enum の 0 番
  （= `session`）に落ちると、別のリミットとして誤って合算される
- **未知の `kind` を捨てない。** 「その他」として素通しで表示する
- **`severity` の順位付けでも未知の値は `normal` ではなく `warning` 扱い。**
  新しい警告レベルが増えたときに見落とさないよう安全側に倒す
- **モデル名をハードコードしない。** `scope.model.display_name` を読んで
  返ってきた分だけ並べる

## 5. 認証は本体に相乗りする

`~/.claude/.credentials.json` の `accessToken` を読むだけ。寿命は約 4.7 時間
なので、常駐していれば必ず期限切れに遭う。それでも自分でリフレッシュはしない。

代わりに **毎回ファイルを読み直す**。Claude Code 本体が動いていれば本体が
トークンを更新して書き戻すので、それに追従する。401 が返ったら
「Claude Code を起動してください」と出して待つ。

### 読み方で守っていること

| 守ること | どうやって |
|---|---|
| 本体の書き込みを妨げない | `FileShare.ReadWrite \| FileShare.Delete` で開く。`FileShare.Read` だけだと本体のトークン書き戻しを塞ぐ |
| 書き込み途中を掴んでも壊れない | JSON が不正なら前回の値を使い続ける |
| 監視しない | `FileSystemWatcher` は tmp+rename を取りこぼす・書き込み途中に発火する・`.claude` 配下の他の書き込みでイベント嵐になる |
| トークンを残さない | 比較にはハッシュ先頭 8 バイトだけを持つ。`DefaultRequestHeaders` にも入れない |
| ログに出さない | `Log.Write` の内部で `Redact()` を強制適用する |

## 6. 行儀よく叩く

Claude Code 本体は同じエンドポイントを内部で 60 秒スロットルしている。
それより速く叩くのは筋が悪く、429 や WAF ブロックを招けば**本体の認証まで
巻き添え**になりうる。

| 守ること | どうやって |
|---|---|
| 60 秒より速く叩かない | 引数でも設定でも 60 秒に丸める。例外を作らない |
| 同時に投げない | `SemaphoreSlim(1)` で直列化 |
| 時刻を揃えない | ±10% のジッタ |
| 2 つ動かさない | 単一インスタンスの Mutex |
| 名乗りを古くしない | User-Agent のバージョンを `~/.claude/sessions/<pid>.json` から読んで追従 |

## 7. 状態は 2 値にしない

常駐して見続けるものなので、「ユーザーが次に何をすべきか」が状態から
分かる必要がある。

| 状態 | 意味 | ユーザーにできること |
|---|---|---|
| `Starting` | まだ 1 回も取れていない | 待つ |
| `Ok` | 新しい値 | — |
| `Stale` | 値はあるが古い | 待つ |
| `Offline` | 通信できない | **無い** |
| `AuthRequired` | 認証が切れた | **Claude Code を起動する** |
| `NotAvailable` | API キー / Bedrock 構成でリミットの概念が無い | — |

`Offline` と `AuthRequired` を分けているのが肝。どちらも「取れない」だが、
前者は待つしかなく、後者はユーザーが直せる。同じ表示にしてはいけない。

`Starting` を空白にしないのも同じ理由で、空白だと「起動していない」と
誤解される。

## 8. 色の決め方

数値の色は **青 → 琥珀 → 赤**。

- しきい値は自前で持たず、サーバーの `severity` に従う
- 数値そのものも併記しているので、色が見分けられなくても情報は失われない
- **緑を使わない。** 赤と緑は第 1・第 2 色覚で区別しづらい。
  青・琥珀・赤なら色相だけでなく明度でも差が残る

## 9. 配置と自動起動

インストーラは作らない。自分自身を `%LOCALAPPDATA%\ClaudeUsageTray\app\` へ
コピーして HKCU の Run キーを書くだけ。

- **固定の場所が要るのは**、自動起動がレジストリに exe のフルパスを書くから。
  `bin\Debug` のままだとビルドし直した時点で壊れ、しかも気づけない
- **`%LOCALAPPDATA%` を選ぶのは** 昇格が不要で Defender の誤検知も少ないから
- **タスクスケジューラを使わないのは** 隠れていて気づかれにくいから。
  Run キーなら「設定 > アプリ > スタートアップ」に現れ、ユーザーが自分で止められる
- **`StartupApproved` も見る。** Run キーに値があってもユーザーが設定画面で
  無効にしていれば起動しない。Run キーだけを見てチェックを付けると
  「有効なのに起動しない＝壊れている」ように見える

## 10. 位置の覚え方

絶対座標では保存しない。**モニタのデバイス名 + 作業領域に対する相対座標
(0.0〜1.0)** で持つ。

絶対座標だと解像度変更やモニタの抜き差しで画面外に飛び、クリック透過と
相まって二度と掴めなくなる。復元時には作業領域内へクランプもしている。

## 11. まだやっていないこと

| 項目 | 備考 |
|---|---|
| 401 後の ShortWatch | `.credentials.json` の mtime を短間隔で見張って即復帰する |
| 指数バックオフ / `Retry-After` | いまは失敗しても同じ間隔で再試行するだけ |
| `resets_at` 直後の前倒し取得 | リセットの瞬間に数字が戻るようにする |
| ローカル JSONL 集計 | トークン数・コスト・現在セッションの消費 |
| しきい値超過の通知 | `severity` が上がった瞬間をトリガにする |
| statusLine 経由のフォールバック | 非公開 API が死んだときの撤退先 |
