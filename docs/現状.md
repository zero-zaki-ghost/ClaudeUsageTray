## 3. 次にやること

### ⓪ 再起動したら 1 回叩く

```powershell
powershell -ExecutionPolicy Bypass -File tools\verify-log.ps1
```

**目視は不要。** 既定で「前回の Windows 起動以降」を判定するので、
再起動後に叩けばそのまま再起動直後の検証になる（§5）。

### ① statusLine フォールバック — [懸念 6](#4-既知の穴)

**残っている最大のリスク。** `/api/oauth/usage` は非公開 API で、
壊れたら「接続できません」と出続けるだけになる。
`~/.claude/settings.json` の statusLine は既に動いており、`rate_limits` を
**受信済みで未使用**。既存の `statusline.mjs` に数行足すだけで足場ができる。

### ② 懸念 2（`Stale`）・懸念 3（403）

どちらも小粒。状態の定義と実装の食い違いを埋めるだけ。

### ③ 懸念 7（完了ダイアログ）

### 懸念 7 の要点

**「ダイアログが出ない」のではなく「見えない場所で応答を待っている」。**
残っていたインストーラのプロセスにウィンドウハンドル・タイトル・応答があった。
所有者つき `MessageBox` を 2 通り試したが改善を確認できず**差し戻した**。

⚠ 検証は**対話的なシェルから手で叩く**こと。エージェント経由だと前景権の
条件が変わり、判定を誤る。

## 5. 確かめたこと / まだのこと

### ⬜ まだ確かめていない — 残り 2 件

どちらも **時間の経過が要るだけ**で、手順は確立している。

#### 暴走型 429 が再発しないこと

| | |
|---|---|
| なぜ未検証か | 本番サーバー相手にしか起きない。**トークンが失効した状態を意図的に作れない** |
| 確かめ方 | **再起動 → Claude Code を起動する前に** `tools\verify-log.ps1` |
| 合格 | `[ OK ] 429` または `[ OK ] 429（単発型のみ）` |

⚠ **単発の 429 は出ても正常。** サーバー都合で起きるもので、バックオフが
受け止める。スクリプトは単発型と暴走型を区別する。

#### 起床シグナルが OS イベントで発火すること

| | |
|---|---|
| なぜ未検証か | **OS イベントを意図的に起こせない。** スリープ・ロック・ネット断はいずれも作業を中断する |
| 確かめ方 | 普通に使っていればいつか起きる。起きたあと `tools\verify-log.ps1` |
| 合格 | `[ OK ] 起床シグナル（OS 由来）` |

> `Wake()` の経路自体は `tests/PollingHarness` で検証済み。残るは **OS が
> イベントを投げてくるか**だけ。スクリプトは手動・テスト由来の起床を OK に
> 数えない（こちらが呼んだだけでは、OS が投げた証拠にならない）。

### 自動で確かめられるもの

**人が判断する必要はない。** コマンド 1 つで判定が出る。

```powershell
powershell -ExecutionPolicy Bypass -File tools\verify-log.ps1   # 実機の状態。7 項目
dotnet run --project tests\PollingHarness                        # 取得まわり。14 項目・約 3 分
```

| | 判定するもの |
|---|---|
| `verify-log.ps1` | 自動起動 / 429 の型 / 失効トークンの扱い / 起床シグナル（**OS 由来だけ**）/ 本体プロセスの検出 / ログのユーザー名漏れ / いま取れているか |
| `PollingHarness` | 失効なら 1 通も送らない / 起床で待機を打ち切る / **下限 60 秒は割らない** / `Retry-After` は起床で破らない / 本体が居ないと 5 倍（**止まりはしない**）|

`PollingHarness` は `CLAUDE_CONFIG_DIR` を一時フォルダへ向けるので
**本物の認証情報を使わない。** 終了コード 0 が全項目 PASS。

### 確かめる予定が無いもの

**「やっていない」ではなく「やらないと決めた」。** 混ぜない。

| 項目 | 理由 |
|---|---|
| UI の自動テスト | パネルの描画・位置記憶は目視のほうが速く確実。自動化の費用が見合わない |
| 通知 / JSONL 集計 | **作らないと決めた**。検証対象ですらない |

## 6. 環境と手順

| 項目 | 内容 |
|---|---|
| OS | Windows 10 / 11 |
| CPU | **x64 のみ**（ARM64 不可） |
| ランタイム | **.NET Desktop Runtime 9**（framework-dependent のため必須） |
| 権限 | 昇格不要（HKCU と `%LOCALAPPDATA%` のみ） |

⚠ **ランタイムが無い環境に自動起動を登録すると、サインイン時に無言で失敗する。**

```powershell
# ビルド・検証・配布
dotnet build   src\ClaudeUsageTray
dotnet run --project tests\PollingHarness
dotnet publish src\ClaudeUsageTray -c Release -o publish

# 配置と解除
.\publish\ClaudeUsageTray.exe --install
& "$env:LOCALAPPDATA\ClaudeUsageTray\app\ClaudeUsageTray.exe" --uninstall

# 状態確認
powershell -ExecutionPolicy Bypass -File tools\verify-log.ps1
Get-Content "$env:LOCALAPPDATA\ClaudeUsageTray\logs\tray.log" -Tail 20
```

| 何 | どこ |
|---|---|
| 本体 | `%LOCALAPPDATA%\ClaudeUsageTray\app\` |
| 設定 | `%LOCALAPPDATA%\ClaudeUsageTray\settings.json` |
| ログ | `%LOCALAPPDATA%\ClaudeUsageTray\logs\tray.log` |
| 生レスポンス | `%LOCALAPPDATA%\ClaudeUsageTray\cache\last-usage.json` |

`cache\last-usage.json` は **API のスキーマが変わったとき diff を取れる唯一の
手がかり**。消さないこと。⚠ `--endpoint` でスタブに向けると上書きされる。
