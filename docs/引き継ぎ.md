## 1. これは何か

Claude Code の使用量（5時間 / 週次 / モデル別リミットの消費率）を、**Windows の画面に常時表示**する常駐アプリ。macOS のメニューバーアプリの Windows 移植として始まった。

```
5h 35% 3:13  │  週 89% 7:03  │  Fable 0% 7:03
```

**現在このアプリは実際に稼働中で、日常利用されている。**

## 5. 未コミットの変更（最初にこれを確認）

`src/ClaudeUsageTray/Platform/Installer.cs` — `ScheduleSelfDelete()` が起動する
`cmd` に `WorkingDirectory = Path.GetTempPath()` を追加した。

**理由**: `UseShellExecute=false` は親プロセスの作業ディレクトリを継承する。
配置先から `--uninstall` を叩くと cmd 自身がそのフォルダを掴んでしまい、
`rd /s /q` で中身は消えても**空フォルダが残る**。実機で踏んで修正した。
修正後、フォルダが完全に消えることを実機で確認済み。

## 6. 既知の穴（未対応）

### 6-1. バックオフが無い（実害を確認済み）

失敗しても 120 秒間隔で叩き続ける。**`Retry-After` を無視する。**

実機のログで **15.5 時間の稼働中に 429 が 3 回**発生している（約465リクエスト中）。
1 回失敗しても次の周期で復帰するので実用上は軽微だが、サーバが締め始めたら悪化する。

### 6-2. `FetchStatus.Stale` が死んでいる

enum に定義があるのに**どこからも代入していない**。UI 側が独自に「5分以上経過」を
見て `N分前` と出しているだけ。状態の定義と実装が食い違っている。

### 6-3. 403 が `NotAvailable` に落ちない

401 以外の HTTP エラーが一律 `Offline` になる。API キー構成や Bedrock/Vertex では
403 が返り「リミットの概念が無い」のが正しい状態なのに「接続できません」と誤表示する。

### 6-4. 401 後の復帰が遅い

`.credentials.json` の mtime を短間隔で見張る ShortWatch が未実装。
`Credentials` の `IsExpired` / `Remaining` / `Fingerprint` はこのために
用意してあるが**現在どこからも呼ばれていない**。

### 6-5. ★ 通知の実装手段が無い

旧設計は `Shell_NotifyIcon` の `NIF_INFO`（バルーン）前提だったが、
**トレイ廃止で手段ごと消えた。** トリガ設計（`severity` の上昇遷移のみ）は有効。

| 案 | 評価 |
|---|---|
| A. 通知専用の隠し `NotifyIcon` | 実装は最小だが「トレイを使わない」方針に逆行 |
| **B. パネル自身を光らせる** | **依存ゼロで方針とも整合。ただし見ていないと気づけない** |
| C. WinRT トースト | 正式だが AUMID 登録等が必要で個人用ツールには重い |

そもそも常時表示なので通知は不要、という判断もあり得る。

### 6-6. ⚠ 完了ダイアログが表示されない（原因未特定）

`--install` / `--uninstall` の `MessageBox.Show` が**表示されないまま即座に戻る**。

- プロセスは 3.2 秒で終了コード 0。ログに例外の記録も無い
- **パネル本体は正常に表示できている**ので、ウィンドウを作れない環境ではない
- 機能自体は全て正しく動く。**フィードバックが無いだけ**
- 一度だけインストーラのプロセスが長く生存した記録があるが、再現しない

→ ユーザーは `--uninstall` しても何の反応も得られない。UX として要改善。

### 6-7. 非公開 API 依存

`/api/oauth/usage` は公開ドキュメントに無い。壊れたら「接続できません」と
出続けるだけになる。撤退線は設計書 14 章にあるが**実装は無い**（Phase 7）。

| 項目 | 状態 |

| 使用量の取得と表示 | ✅ 実データで確認 |
| マルチモニタでの位置記憶 | ✅ 3画面環境で、再起動と配置先変更をまたいで復元を確認 |
| ドラッグ移動・右クリックメニュー | ✅ |
| `--install`（配置・Run キー登録・起動） | ✅ |
| `--uninstall`（プロセス停止・Run キー削除・フォルダ完全削除・設定保持） | ✅ |
| 完了ダイアログ | ❌ 出ない（6-6） |
| **サインアウト→サインインでの自動起動** | ⬜ **未検証** |
| 長時間の安定性 | △ 15.5時間の連続稼働でメモリ 17MB 安定、429 以外のエラー無し |
| 単体テスト | ❌ 無し（`tests/` は未作成） |

### 自動起動の検証手順

**アプリは起動種別をログに記録する。** Run キー経由なら `startup=True`、手動なら `False`。
現時点で `startup=True` の行は 1 度も無い。

1. サインアウト → サインイン（⚠ **実行中の作業は全て閉じる**）
2. 画面にパネルが出ることを目視
3. 決め手:

```powershell
Select-String "$env:LOCALAPPDATA\ClaudeUsageTray\logs\tray.log" -Pattern "startup=True" | Select-Object -Last 1
```

サインイン直後の時刻でこの行が出れば成功。

> explorer.exe の再起動では Run キーの再実行が保証されないので検証手段にならない。

## 8. 踏んだ罠（再発させないこと）

実機で実際に踏んで直したもの。コード中にも同じ注記がある。

| # | 罠 |
|---|---|
| 1 | **Windows の通知領域は 16×16 のアイコン 1 枚しか置けない。** macOS の可変幅テキストに相当するものは無い。しかも Win11 は既定でオーバーフローに隠す。→ トレイ方式そのものを廃止した |
| 2 | **`TextRenderer`(GDI) はアルファを書かない。** 32bpp ARGB に描くと文字が透明になる。GDI+ の `DrawString` を使う |
| 3 | **`WS_EX_TRANSPARENT` は `CreateParams` に含める。** `SetWindowLongPtr` で後付けすると `Opacity` 変更時に WinForms が作り直して消す |
| 4 | **`GenericTypographic` は末尾の空白を幅に数えない。** `MeasureTrailingSpaces` が無いと文字が詰まる |
| 5 | **`NotifyIcon` は `Icon` を入れてから `Visible=true`。** 逆だとシェルに登録されない |
| 6 | **`Process.Start` の前に単一インスタンスの Mutex を手放す。** 握ったままだと新プロセスが即終了し、常駐が全滅する |
| 7 | **`UseShellExecute=false` は親の CWD を継承する。** 自分を消すプロセスの CWD が消す対象だと空フォルダが残る |
| 8 | **`Screen.PrimaryScreen` だけで画面を撮ると、別モニタのウィンドウを「消えた」と誤判定する。** `SystemInformation.VirtualScreen` か `GetWindowRect` を使う |
| 9 | **`sed` で非 ASCII（`■`）やバックスラッシュを置換すると黙って失敗する。** Node/Python でリテラル置換し、必ず grep で再確認する |
| 10 | **「https なら許可」はトークン送信先の対策にならない。** 攻撃者も証明書を用意できる。ホストまで固定すること |

## 9. 環境と手順

### 必要なもの

| 項目 | 内容 |
|---|---|
| OS | Windows 10 / 11 |
| CPU | **x64 のみ**（`RuntimeIdentifier=win-x64`。ARM64 不可） |
| ランタイム | **.NET Desktop Runtime 9**（framework-dependent のため必須） |
| 前提 | Claude Code にサインイン済み |
| 権限 | 昇格不要（HKCU と `%LOCALAPPDATA%` のみ） |

⚠ **ランタイムが無い環境に自動起動を登録すると、サインイン時に無言で失敗する。**

### よく使うコマンド

```powershell
# ビルドと配布
dotnet build   src\ClaudeUsageTray
dotnet publish src\ClaudeUsageTray -c Release -o publish    # 単一 exe 228KB

# 配置と自動起動の登録 / 解除
.\publish\ClaudeUsageTray.exe --install
& "$env:LOCALAPPDATA\ClaudeUsageTray\app\ClaudeUsageTray.exe" --uninstall

# 状態確認
Get-Process ClaudeUsageTray
Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name ClaudeUsageTray
Get-Content "$env:LOCALAPPDATA\ClaudeUsageTray\logs\tray.log" -Tail 20
```

### 置き場所

| 何 | どこ |
|---|---|
| 本体 | `%LOCALAPPDATA%\ClaudeUsageTray\app\` |
| 設定 | `%LOCALAPPDATA%\ClaudeUsageTray\settings.json` |
| ログ | `%LOCALAPPDATA%\ClaudeUsageTray\logs\tray.log` |
| 生レスポンス | `%LOCALAPPDATA%\ClaudeUsageTray\cache\last-usage.json` |

`cache\last-usage.json` は**API のスキーマが変わったとき diff を取れる唯一の手がかり**。消さないこと。

## 10. 触るときの不変条件

破ると壊れる。詳細は [`設計.md`](設計.md) 0 章。

1. **自前で OAuth トークンをリフレッシュしない**（本体のセッションが壊れる）
2. **`.credentials.json` は `FileShare.ReadWrite | FileShare.Delete` で開く**（本体の書き戻しを塞がない）
3. **`~/.claude` に書き込まない**
4. **ポーリング間隔の下限 60 秒**（引数でも設定でも破れないようにする）
5. **`limits[]` の `kind` / `severity` を enum にしない**（未知の値が 0 番に落ちて誤合算する）
6. **しきい値を自前で決めない**（サーバーの `severity` に従う）
7. **未文書化のシェル API に手を出さない**
8. **UI を殺せる設定を作らない**（メニューに辿り着けなくなり終了もできなくなる）
