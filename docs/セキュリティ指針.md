# 他人のアプリに相乗りするツールを作るときの指針

> このアプリは **Claude Code 本体の認証情報を読み、本体と同じ内部 API を叩く**。
> つまり「他人のアプリに相乗りする」タイプのツールで、壊すと被害が本体に及ぶ。
>
> ここに書いてあるのは、**実際に作って運用する中で踏んだこと**から抽出した、
> プロジェクトに依存しない規則。同じ形のツールを作る人に向けて切り出してある。
> このアプリでの適用は [`設計.md`](設計.md) 19 章。

---

## ★ 最重要: 「対策したつもり」を文書化しない

**実際に防げる範囲だけを書く。**

不完全な対策を完全であるかのようにコメントやドキュメントに書くと、
後から読んだ人が守られていると誤解し、**そこで思考が止まる**。
**何も書かないより有害。**

### 実際に踏んだ例

送信先を `https` に限定して「トークンを任意のサーバへ送らせるのを防ぐ」と
書いた。しかし攻撃者は自分のサーバに証明書を用意できるので、
`https://evil.example.com/` は素通りだった。

**TLS は経路を守るだけで、送り先が正しいことは保証しない。**

対策を書くときは必ず自問する:

> **これを書いた攻撃者なら、どう回避するか。**

### 派生: 「実装した」と「確かめた」を分ける

動かして確かめていないものを「対応済み」と書かない。
このリポジトリでは状態を [`現状.md`](現状.md) に集め、
**未検証の項目には「なぜ未検証か」「どうすれば確かめられるか」まで書く**。

確かめる手段が無いなら、それ自体が設計の問題。

## 1. 本体の認証を壊さない

### 自前でトークンをリフレッシュしない

技術的に可能でも、やらない。**被害が非対称**だから。

| | 失うもの |
|---|---|
| このツールが動かない | 「数字が見えない」だけ |
| 本体の認証が壊れる | **仕事が止まる** |

リフレッシュにはレート制限や WAF ブロックの既知問題があり、失敗すると
本体のセッションごと壊れうる。**毎回ファイルを読み直して本体に追従する**
ほうが、得られるものと失うものが釣り合う。

### 読むだけ。ロックしない

- **書き込まない。**
- **排他で開かない。** 読み取り中でも相手が書き換え・削除できる共有モードで開く
  （.NET なら `FileShare.ReadWrite | FileShare.Delete`）。
  排他で開くと、**相手のトークン書き戻しをこちらが失敗させる**
- **壊れた内容を掴んだら前回値を使い続ける。** 相手が書き込み途中なだけの
  可能性が高く、そこで「認証エラー」を出すのは誤報
- **監視しない。毎回読む。** `FileSystemWatcher` は tmp+rename を取りこぼし、
  書き込み途中で発火し、無関係な書き込みでイベント嵐になる

---

## 2. 送信先を許可リストで限定する

**「https なら OK」は対策ではない。ホストまで固定する。**

検証用にエンドポイントを差し替える引数を持つなら、

- 本番と**同じホスト**宛て、または
- **ループバック**（`127.0.0.1`）宛て

だけを許す。それ以外は無視してログに残す。

> 差し替え可能にすること自体は悪くない。**差し替え先を絞らないこと**が悪い。

---

## 3. 相手より速く叩かない

本体が内部でスロットルしているなら、**それより速く叩く理由は無い**。

### 下限は「唯一の出口」で強制する

これも実際に踏んだ。下限 60 秒を**呼び出し側の作法**で守っていたため、
メニューの「今すぐ更新」だけが素通りし、連打すれば連打しただけ飛んだ。

**強制する場所は、実際に送信する関数の中。** そこを通らずに送れないなら、
誰がどう呼んでも破れない。

### 送る前に分かることは、送る前に判断する

**失効しているトークンを送って 401 で確かめない。**
`expiresAt` を読めば送信前に分かる。

実測: 失効トークンを 2 分おきに投げ続けたところ、**401 が 3 回続いた時点で
サーバーが 429 に切り替え**、本体を起動するまで 12 分間エラーになった。
**2 回の独立した再現で同じ境界を確認**している。

> これは PC を再起動するたびに必ず起きていた。
> 再起動直後はトークンが失効しており、本体が起動するまで誰も更新しないため。

### 失敗したら間隔を空ける

指数バックオフを入れる。`Retry-After` が来たら**それを最優先**で尊重する。

⚠ **`Retry-After` には 2 つの形式がある。**

```
Retry-After: 120                             秒数
Retry-After: Wed, 23 Sep 2026 20:00:00 GMT   絶対時刻
```

片方しか読まずに「尊重した」と書くのは、冒頭の「対策したつもり」そのもの。

## 4. 認証情報を持ち回らない

| 守ること | やり方 |
|---|---|
| メモリに保持しない | ローカル変数に留める。常駐オブジェクトに置かない。同一性の比較が要るならハッシュの先頭数バイトで足りる |
| ログに出さない | **マスクをログ出力関数の内部で強制する**（下記） |
| 例外を素通ししない | `ex.ToString()` はリクエスト情報を含みうる。**型名と短いメッセージだけ**出す |
| ディスクに書かない | レスポンスを保存するならボディだけ。**リクエストヘッダは絶対に保存しない** |
| 検証に本物を使わない | スタブ相手のテストは偽のトークンで足りる。**本物の資格情報を動かす必要はどこにも無い** |

### マスクは出力の直前に置く

**呼び出し側に「気をつけて書く」を求めない。** 必ずいつか破られる。
ログ出力関数の中で強制的にマスクを通せば、誰が何を渡しても伏せられる。

### 伏せる対象はトークンだけではない

**絶対パスにはユーザー名が入る。**
`C:\Users\<名前>\…` がそのままログに残り、トラブル報告で人に見せた瞬間に漏れる。

これも実際に踏んだ。トークンのマスクだけ実装して満足していた。

## 5. 公開する前に

**一度公開すると取り消せない。** push・可視性変更の**前**に確認する。

### author のメールアドレス

```bash
git log --all --format='%ae%n%ce' | sort -u
```

⚠ **履歴を書き換えただけでは直らない。** `git filter-branch` で過去を
noreply に直しても、**repo ローカルの設定が無ければ次のコミットでまた戻る**。

```bash
git config user.email "<id>+<name>@users.noreply.github.com"
```

実際に、公開後の最初のコミットで個人アドレスが載る寸前だった。

### 全履歴の中身

```bash
for c in $(git rev-list --all); do git grep -l "<キーワード>" $c; done
```

ローカルパス（ユーザー名が入る）・ホスト名・内部 URL・顧客名。
**HEAD だけ見ても不十分。過去のコミットに残る。**

> ⚠ 非 ASCII 文字やバックスラッシュを含む置換を `sed` で書くと、
> エスケープが多重になって**黙って失敗する**。
> スクリプト言語でリテラル置換し、**置換後に必ず grep で再確認**する。

### ビルド成果物

`bin/` `obj/` `publish/` には**絶対パスが埋め込まれる**。
`.gitignore` 済みか `git ls-files` で確認する。

---

## 6. 共有すべきでないこと

この種のツールの知見を人に渡すとき、**渡してはいけないものがある**。

| | 理由 |
|---|---|
| 非公開 API の叩き方そのもの | 広まるほど塞がれる圧力が上がる。**自分の首を絞める** |
| レート制限の回避手段としての説明 | 3 章の趣旨は「相手より速く叩くな」であって、制限のかいくぐり方ではない |

指針の文脈で必要な範囲に留める。

## チェックリスト

認証情報・外部送信・公開範囲に関わる変更をしたら、これを通す。

```
□ 「対策したつもり」を書いていないか。攻撃者ならどう回避するか自問したか
□ 実装しただけのものを「対応済み」と書いていないか
□ 送信先はホストまで固定されているか（https だけでは不可）
□ 送信間隔の下限は、呼び出し側ではなく送信関数の中で強制しているか
□ 送る前に分かることを、送ってから確かめていないか
□ Retry-After は 2 形式とも読んでいるか
□ ログのマスクは出力関数の内部で強制されているか
□ マスクの対象に絶対パス（ユーザー名）が入っているか
□ 例外をそのまま出していないか
□ 検証に本物の資格情報を使っていないか
□ （公開前）author メール / 全履歴 / ビルド成果物を確認したか
□ 残存リスクを隠さず書いたか。「対応しない」と決めたものこそ明示したか
```
